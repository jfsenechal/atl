  Changes
  - config/packages/messenger.yaml: I removed the SendEmailMessage: async
    routing. Mail that isn't routed is sent right away.
  - New Mailer/BulkMailer.php: it builds the mail once, then puts one copy per
    address on the async queue. Empty and duplicate addresses are skipped. The
    mail is built before queuing because the worker has no web request to build
    it from.
  - Message/Handler/MessageHandler.php: it now uses BulkMailer and returns how
    many mails were queued.
  - Message/Factory/EmailFactory.php: the attachment's content is now read when
    the message is created. Before, the mail only kept the path to the uploaded
    temporary file, which is deleted by the time the worker sends the mail, so
    queued mails would have lost their attachment.
  - Controller/Admin/MessageController.php: the confirmation now reads "N
    mail(s) mis en file d'envoi, ils partiront dans les prochaines minutes"
    instead of "envoyé", because the mails haven't left yet.
  - Tests: a new tests/Mailer/BulkMailerTest.php checks that each address gets
    one queued mail on async, with the content filled in. In MailDebuggerTest,
    the routing check now expects direct sending.
  - DEPLOY.md, section 9: updated to describe the new behaviour.

  Things to know:
  - The hourly limit: mail sent directly doesn't count toward the mailer hourly
    limit. Only the queue worker and the invoice cron count. Normal traffic
    (registrations, login links) is low, so I left it that way.
  - Mail already in the queue: anything already waiting in async will still be
    sent by the worker. Nothing is lost.
  - Production still redirects all mail: when@prod in mailer.yaml still sends
    every mail to webmaster@marche.be, as I flagged earlier. I left it alone.

  I haven't committed anything. Your earlier fix (dec7cd4) was already in place.
